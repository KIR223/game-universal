# Android

**Статус:** debug APK собирается и подписывается (arm64-v8a для телефона, x86_64 для эмулятора; minSdk 24, targetSdk 36). **Проверено в эмуляторе** (Android 35 x86_64, Google APIs, хост-GPU): главное меню, список сценариев, касанием запущен «Современный мир», выбор государства с реальной картой всех 205 стран отображается. **На физическом устройстве не запускался.** 
## Проверено в эмуляторе (касания через `adb input`)
- Меню → Сценарии → «Современный мир» → выбор государства (Индия) → игра: HUD, реальная карта, карточка ячейки, камера на столице.
- Свайп двигает карту, тап выбирает ячейку и открывает карточку, кнопки скорости, меню ☰ и варианты событий нажимаются.
- Симуляция: ~100 дней на скорости 3 без `SCRIPT ERROR`, память ≈ 424 МБ PSS и не растёт.
- Сохранение в `files/saves/quick.sav` и загрузка через меню: после сохранения на 10 апреля игра дошла до 22 мая, загрузка вернула 10 апреля.

## Сборка в CI
Задача `android debug APK` в `.github/workflows/ci.yml` (ubuntu-latest): JDK 17, Android SDK (`build-tools;36.1.0`, `platforms;android-36`), Godot export templates, временный debug-ключ (создаётся `keytool` прямо в задаче, секретов нет), экспорт двух debug APK, проверка `apksigner verify` и размера (> 36 МБ; без `data/world` APK ≈ 28 МБ), артефакт `IRON-DOMINION-ANDROID-DEBUG` (`IronDominion-debug.apk` arm64, 37.8 МБ; `IronDominion-debug-x86_64.apk` для эмулятора, 40.4 МБ).
Проверено: артефакт скачан, x86_64-APK из CI установлен на эмулятор и открыл «Современный мир» с картой всех стран. Ключ CI отличается от локального: при смене сборки на эмуляторе нужен `adb uninstall com.kir223.irondominion` (иначе `INSTALL_FAILED_UPDATE_INCOMPATIBLE`). arm64-APK из CI на устройстве не запускался.

## Сенсорная адаптация (ветка `feature/android-touch`)
- Масштаб интерфейса на телефоне считается из DPI: `clamp(dpi/300, 1.0, 1.5)` (420 dpi → 1.4); на десктопе 1.0. Значение 1.75 пробовал — панели HUD слишком сжимались.
- Долгое нажатие (450 мс без движения) на карте = правый клик, т.е. открывает контекстное меню (война, союз, эмбарго, центрирование); только на мобильных (`OS.has_feature("mobile")`).
- Экран сценариев прокручивается (раньше «Назад» уходил за экран), подпись с источниками данных переносится, панель выбора страны подгоняется под высоту экрана.
- Проверено в эмуляторе (420 dpi, 2400×1080): долгое нажатие открывает меню с «Объявить войну: Непал», «Предложить союз», «Эмбарго»; свайп прокручивает список сценариев.

## Автосохранение (ветка `feature/android-autosave`)
- При уходе приложения в фон (`NOTIFICATION_APPLICATION_PAUSED`) идущая игра пишется в слот `auto` (`user://saves/auto.sav`), формат сохранений общий.
- В главном меню появляется «Продолжить (автосохранение)», если слот есть.
- Проверено в эмуляторе: Индия, 2 января → кнопка Home → `auto.sav` записан (≈ 538 КБ) → процесс убит `force-stop` → запуск → «Продолжить» вернул ту же игру (дата, казна 975 (+178), отложенное событие).
- Ограничение: сохраняется только при сворачивании; если систему убьёт приложение без события паузы (краш, нехватка памяти в активном состоянии), последние дни игры потеряются. Периодического автосохранения нет.

- Один раз при выборе страны тап по списку, похоже, ещё и выбрал ячейку карты под пальцем (клик «сквозь» экран); повторить не удалось, причина не выяснена.

- Физический телефон, FPS и нагрев на мобильном GPU, мобильные профили графики (нужны замеры на реальном телефоне, на эмуляторе с моим GPU они бессмысленны).

## Рендерер
Vulkan (Forward Mobile) на эмуляторе даёт чёрный экран (`Couldn't present to Vulkan queue`) и с хост-GPU, и с SwiftShader. Для Android включён Compatibility (OpenGL ES): `renderer/rendering_method.android="gl_compatibility"` (только Android, desktop/iOS не затронуты). С программным GL (SwiftShader) интерфейс не рисуется (лимит uniform), с хост-GPU эмулятора (`-gpu host`) всё работает. Как поведёт себя реальный телефон — не проверено.

## Эмулятор
`avdmanager` в этой версии создаёт AVD с `avd.name=<build>` и нулевым экраном — в `config.ini` исправлены имя, `hw.lcd.*`, `hw.gpu.mode=host`, `disk.dataPartition.size=3G` (на диске C: мало места). Запуск: `emulator -avd iron_test -gpu host`; пакет — `com.kir223.irondominion/com.godot.game.GodotAppLauncher`.

## Инструменты (Windows, установлены вне репозитория)
- JDK 17: `winget install Microsoft.OpenJDK.17` → `C:\Program Files\Microsoft\jdk-17.0.21.21-hotspot`
- Android SDK (cmdline-tools из dl.google.com): `%LOCALAPPDATA%\Android\Sdk` — `platform-tools`, `platforms;android-36`, `build-tools;36.1.0`, `ndk;29.0.14206865` (версии из `android_source.zip` шаблона Godot 4.7.2).
- Godot export templates 4.7.2 (`%APPDATA%\Godot\export_templates\4.7.2.stable`).
- Godot Editor Settings: `export/android/android_sdk_path`, `export/android/java_sdk_path`, `export/android/debug_keystore` (debug-ключ создаётся `keytool`, в репозиторий не кладётся).

## Сборка debug APK
```
godot --headless --path . --import
godot --headless --path . --export-debug "Android debug APK" build/android/IronDominion-debug.apk
adb install -r build/android/IronDominion-debug.apk
```
Нужна настройка проекта `rendering/textures/vram_compression/import_etc2_astc=true` (добавлена; нужна и для iOS).
