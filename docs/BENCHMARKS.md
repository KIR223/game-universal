## Что сделано для скорости
- Карта рисуется шейдером по палитре на ячейку: смена владельца = один пиксель палитры; границы вычисляются на GPU.
- Векторные слои (дороги, ж/д, реки, границы) разбиты на чанки 15° и превращены в готовые меши; рисуются только видимые чанки и только по уровню масштаба.
- Города — колонки типизированных массивов (а не 70 тыс. словарей), индекс по чанкам строится в рабочем потоке; точки рисуются двумя пакетными вызовами; подписи — без наложения.
- Симуляция: кеши списков ячеек по странам, кеш соседей, точная (с ключом версии) агрегация экономики, ограниченный по дальности и ленивый (раз в 3 дня) расчёт снабжения.
- Кадр интерфейса ограничен по времени: на высокой скорости симуляция отстаёт, а не подвешивает окно.

Известные ограничения: при ≥ 8 днях/с симуляция не успевает (≈ 50 мс/день); векторные линии при максимальном приближении тонкие (1 px).

## Отрисовка населённых пунктов (Windows, RTX 5060 Ti, 120 Гц, VSync выкл.)

`tools/profile_frame.gd -- <zoom> 300` — кадры при движении камеры по реальному миру. Узкое место было в GDScript, не в GPU (GPU ≈ 0.1 мс, render CPU ≈ 0.5 мс): `_draw_settlements` перебирал все пункты видимых чанков и отсеивал по порогу населения. Теперь пункты в чанках отсортированы по населению, цикл прерывается на пороге, столицы ниже порога хранятся отдельно (`_cap_chunks`).

| Масштаб | До | После |
|---|---|---|
| 0.25 | 18.5 мс (54 FPS) | 5.8 мс (172 FPS) |
| 1.0 | 19.8 мс (50 FPS) | 9.1 мс (110 FPS) |
| 4.0 | 10.7–18.3 мс (шумит) | 10.6 мс (95 FPS) |

Игровое состояние, `checksum()` и сохранения не затронуты (только рендер).

### Игровой день: что было медленным
Узким местом был не GPU и не интерфейс (обновление HUD ≈ 3.8 мс), а `Simulation.tick_day()` в главном потоке: ≈ 82 мс/день в середине игры (205 стран, 91 союз, 322 армии).
Профиль по шагам (мс/день, среднее за 40 дней):

| Шаг | До | После | Причина и исправление |
|---|---|---|---|
| `_supply` | 39.8 | 12.1 | в цикле по соседям каждой ячейки вызывались `allied()`/`at_war()`, линейно сканирующие все союзы/войны → отношение к владельцу кешируется на время поиска |
| `_resources` | 12.1 | 3.9 | `army_strength()`/`armies_of()` на каждую страну сканировали все армии (O(стран × армий)) → армии группируются по владельцам за один проход |
| `_logistics` | 11.9 | ≈ 0 в дни без изменений | блокада — чистая функция владельцев ячеек, позиций флотов, войн и союзов; пересчёт только при изменении этих входных данных |
| остальное (`_ai`, `_economy`, `_politics`, …) | 18.1 | ≈ 18 | не менялось |
| **Итого** | **81.8** | **33.9** | |

Точность: контрольные суммы `checksum()` старой и новой версии **побитово совпадают** на сценариях «Современный мир», «Хаос», «Холодные блоки» в 5 точках за 365 дней (73/146/219/292/365), эталоны из #15 не изменились. Год в «Современном мире»: 40.3 с → 20.1 с.

### Ускорение времени (сессия с HUD, кадр и дни в секунду)
| Скорость | Дни/с до → после | Кадр до → после |
|---|---|---|
| ×1 | 1.0 → 1.0 | 8.7 → 8.6 мс (116 FPS) |
| ×3 | 2.9 → 3.0 | 10.0 → 9.3 мс (108 FPS) |
| ×8 | 7.9 → 8.0 | 23.2 (p95 106) → 10.9 мс (p95 46), 43 → 92 FPS |
| ×20 | 8.6 → 15.6 | 117 → 64 мс, 9 → 16 FPS |

Известное ограничение: симуляция идёт в главном потоке, поэтому на ×20 один игровой день (≈ 34 мс) всё ещё превышает бюджет кадра: плавность интерфейса падает, дни идут быстрее ≈ 15/с. Вынос симуляции в отдельный поток потребует разделения чтения/записи состояния (не делалось).

### Качество графики (кадр при движении камеры, мс; меньше — лучше)

## Кадры в окне (macOS M1, `tools/benchmark_frames.gd`, 300 кадров)
| Сценарий | Перемещение камеры | Масштабирование 0.2 → 8 |
|---|---|---|
| modern_world (14 тыс. ячеек) | 23 мс (43 FPS) до оптимизации | 23 мс (43 FPS) до оптимизации |
| modern_world_hd | 64 мс (16 FPS) до → **7 мс (143 FPS)** после | 50 мс (20 FPS) до → **16 мс (62 FPS)** после |
| modern_world_xl | 66 мс (15 FPS) до → **8 мс (119 FPS)** после | 52 мс (19 FPS) до → **18 мс (57 FPS)**, p95 37 мс |
Причина просадки: каждый кадр перебирались все пункты видимых чанков (237 тыс.). Теперь внутри чанка сначала столицы, затем пункты по убыванию населения, цикл останавливается на первом пункте ниже порога.

## Год игры на XL со всеми правилами (terrain, weather, modern; headless)
365 дней: 67,7 с (среднее ≈ 185 мс/день, худший день 360 мс); к концу 3 войны, 205 живых стран, 331 армия; сохранение/загрузка даёт ту же контрольную сумму. Среднее за первые 30 дней было ≈ 91 мс: стоимость растёт вместе с числом армий и войн.

## Оптимизация игрового дня (XL, со всеми правилами)
Профиль по фазам (середина года, мс/день): снабжение 97 → 36, экономика 45 → 2,4, логистика/блокады 21 → ~0, ресурсы 12,8 → 3,5.
Год игры: 68 с → **23,6 с** (среднее ≈ 65 мс/день, худший день 360 → 189 мс). Контрольные суммы сценариев до и после оптимизации совпадают; добавлен тест на равенство инкрементальной агрегации полной пересборке.
Приёмы: множества врагов/союзников вместо перебора войн на каждый шаг поиска снабжения, кеш промышленности страны, инкрементальные суммы по странам при смене владельца ячейки, пропуск проверки блокад у стран без вражеского флота, один проход по армиям вместо перебора для каждой страны.
