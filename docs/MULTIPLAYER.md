# Мультиплеер

Кросс-платформенная игра по сети (Windows ↔ macOS ↔ Linux ↔ Android): **авторитетный хост + детерминированный lockstep**.
Код: `game/multiplayer/`, интеграция в игру — `game/ui/main.gd` (раздел «multiplayer»), тесты — `tests/run_net_*.gd`, `tests/net_enet_test.py`.

## Как это работает
- У хоста настоящая `Simulation`. Каждая команда проходит `Simulation.apply_command()` **у хоста** (там же валидация) и рассылается всем как событие `ev`; каждый игровой день хост считает сам и объявляет сообщением `tick`.
- Клиенты **не двигают время сами**: у каждого своя копия `Simulation`, которая применяет `ev` и `tick` строго по порядку (один надёжный упорядоченный канал ENet). Время синхронизировано по построению; паузой и скоростью владеет хост (клиент может попросить паузу).
- По сети идут только команды и тики дней (в тихий день ≈ 50–100 байт на клиента), **не карта**. Полное состояние (≈ 50 КБ после zstd) уходит один раз — при входе и при ресинхронизации.
- Контрольная сумма `Simulation.checksum()` (теперь включает `legal[]`) приходит в `tick` каждые `checksum_every` (5) дней. Расхождение или ошибка применения события = **desync**: клиент просит снимок, хост присылает, игра продолжается. Больше 5 пересинхронизаций на игрока — игрок отключается («too many desyncs»).
- Клиентская `Simulation` пересылает команды хосту через `command_sink`; хост рассылает через `command_hook`. Команды, которые симуляция выдаёт себе сама во время `tick_day()` (строительство ИИ), хуки не трогают: каждый пир воспроизводит их детерминированно.

## Рукопожатие (`hello` → `welcome` | `reject`)
Хост отклоняет вход, если не совпадают: версия протокола (`NetProtocol.VERSION`), `world_hash` набора геоданных (стабильные ID ячеек), `SAVE_VERSION`, **отпечаток правил** (контрольная сумма короткого детерминированного прогона симуляции — ловит разные версии сборки и разную арифметику платформ ещё при входе), страна занята/недоступна, мест нет. Страна клиента — запрошенная или первая свободная; остальные остаются ИИ.

## Безопасность и устойчивость
- До `hello` хост ничего не принимает. Команда клиента проверяется на «здравость» (словарь из простых значений, ограничения по размеру) и на **свою страну** (`cmd.country` = страна игрока); игровые правила проверяет сама симуляция.
- Мусорные и неизвестные сообщения игнорируются, хост не падает.
- **Отключение**: страна игрока автоматически переходит под ИИ (событие рассылается всем, хост и клиенты остаются идентичными). **Переподключение**: клиент входит с выданным токеном и получает ту же страну и снимок (меню ☰ → «Переподключиться к хосту»).
- **Сетевые сохранения**: хост сохраняет игру обычным `SaveSystem` (F5); снимок для сети = тот же `to_dict()`.

## Как играть
Главное меню → «Сетевая игра». Хост: «Создать игру (Современный мир)» → выбрать страну → игра на паузе, порт UDP 24680 (`NetProtocol.DEFAULT_PORT`) должен быть доступен (в локальной сети — адрес хоста; через интернет нужен проброс порта). Клиент: адрес хоста и порт → «Подключиться». Скорость и паузу задаёт хост.
Только для проверки: `godot --headless --path . -s tools/net_selftest.gd -- host|client <порт> <дни>`.

## Ограничения (честно)
- **Windows ↔ macOS по сети я не запускал**: CI гоняет хост и клиент на одной ОС; кросс-платформенность подтверждена детерминизмом (эталонные `checksum()` совпали на Windows, macOS и Linux) и платформонезависимой сериализацией (`var_to_bytes`), а отпечаток правил отсекает несовместимые сборки при входе.
- Нет: лобби/списка игр, шифрования и аутентификации (токен — не секрет), проброса портов/NAT-traversal, голосового и текстового чата, выбора сценария клиентом (хост всегда «Современный мир»), одновременного выбора страны клиентом до входа (берёт первую свободную), зрителей.
- События с выбором (всплывающие окна) ставят на паузу только собственный интерфейс игрока; хост при своём событии останавливает часы для всех.
- Хост считает день в главном потоке (≈ 34 мс): при ×20 у всех игроков интерфейс будет тормозить так же, как в одиночной игре.
- Любое изменение правил симуляции меняет отпечаток правил: игроки с разными сборками не смогут играть вместе (это намеренно). Поднимайте `NetProtocol.VERSION` при несовместимых изменениях сообщений.
