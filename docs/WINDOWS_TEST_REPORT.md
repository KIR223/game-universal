- Экран выбора страны, карта с границами, городами, дорогами, реками, названиями, события, панель ячейки (Мазовецкое воеводство, Варшава), армии — отображаются.

- 1366×768: HUD и панели помещаются, читаемо. 1600×900: ок.
- 3840×2160: окно ОС ограничило размер до 1924×1061, настоящий 4K не проверен. DPI-масштаб не проверен.
- Fullscreen/borderless и ввод мышью/клавиатурой вручную не проверялись.

### Найденные дефекты
1. ~~Экран выбора страны: карта не центрирована~~ — **снято, не дефект**: камера использует сглаживание позиции (`position_smoothing_speed = 14`), ранний снимок поймал её в движении. Через ~160 кадров карта заполняет окно и центрирована. В `tools/screenshot_earth.gd` добавлена задержка.
2. **FPS камеры ≈50** при 1085 вызовов отрисовки (см. выше). Не профилировано.

## Совместимость с macOS и сквозная война (PR #15)
- Сквозной тест войны на реальной карте только через команды (`declare_war`, `move_army`): `legal[]` не меняется, `owner[]` меняется по ячейкам, детерминизм и сохранение/загрузка посреди войны — OK.
- Эталонные `checksum()` (30 дней без войны, 40 дней войны), записанные на Windows, **совпали на macOS и Linux в CI**. Это сильное, но не полное доказательство совместимости мультиплеера Windows ↔ macOS: проверены только эти сценарии, сеть не тестировалась.
- Совместимость самих файлов сохранений между физическими ПК не проверялась отдельно; формат — `var_to_str(sim.to_dict())`, текстовый и платформонезависимый.

## Артефакт CI `IRON-DOMINION-WINDOWS-X64`
Скачан из GitHub Actions (run на `platform/windows`), распакован в пустую папку: `IronDominion.exe` (104.5 МБ), `README.md`, `ASSET_LICENSES.md`. Запущен вне проекта и редактора: окно «Iron Dominion» создаётся, процесс отвечает через 10 с (~488 МБ RAM), рядом с EXE лишних файлов нет. Ограничение: проверка на этом же ПК, где установлен Godot, а не на «чистой» Windows/VM; информации о версии и лицензий в артефакте минимум (README и ASSET_LICENSES).
